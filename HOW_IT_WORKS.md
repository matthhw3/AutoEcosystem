# Architecture and decisions

Current development status: the initial playable is complete, while the broader product is still under active implementation. A milestone checkmark means its listed work was tested, not that the whole game is finished.

The active persistent goal uses RELEASE_ACCEPTANCE.md as its bounded completion contract and RELEASE_AUDIT.md for independent evidence. Milestones trigger tested commits and further work, rather than ending development.

Shared habitat geometry now lives in `scripts/habitat.gd`: deterministic tree records drive both the forest renderer and circular trunk obstacles. An 8m spatial grid bounds movement and sight queries. Swept collision prevents tunneling; local steering and sliding avoid trunks. Sight rays test trunk occlusion. This is local obstacle avoidance, not a global path planner. Habitat QA compares grid visibility against exhaustive geometry and checks movement/boundary invariants.

M4 replaces global grazing with localized meadow/water resources. Animals discover nearby visible resources and retain resource IDs in food/water memory, then travel back when hungry/thirsty. Grazing and drinking consume biomass; normal weather regenerates it and drought/fire/flood reduce availability. The forage HUD is the mean meadow biomass. Thirst, depletion and dehydration now affect survival.

Individual boldness changes predator-detection distance, while endurance changes stamina cost. Nearby wolves can adopt a pack member's prey target and share a successful meal. Initial worlds contain 3 wolves and 6 deer; v1 saves preserve their original population. Wolf hunger gain is 0.025 points/second for compressed observation pacing, balanced through seeded coexistence tests rather than literal metabolic units.

Save schema v2 adds resources, thirst, traits and food/water memories. v1 files migrate with neutral traits and default resources without advancing time. Validation rejects malformed additions before mutating state. Population capacity now counts only living animals (36 maximum); up to 128 total records retain recent deaths for inspection. Oldest deaths are pruned beyond that bound, targets are repaired and the view removes stale proxies. Dead records no longer permanently prevent births.

Godot 4.7.2 / GDScript, compatibility renderer for reliable startup. Procedural low-poly forest prioritizes readable animal behavior. The renderer can be upgraded after profiling; no dependency on an online service.

`scripts/simulation.gd` owns serializable agent state and seeded randomness independently of the scene tree. Fixed 0.1-second ticks run only after Start or explicit Step. Biological needs feed individual behavior choices, while danger and recent experiences persist across ticks/saves. Time scaling schedules extra fixed ticks; camera and UI stay interactive while paused.

`scripts/forest.gd` builds procedural scenery and supplies terrain height. `scripts/spectator_camera.gd` owns free flight/follow. `scripts/main.gd` integrates model, animal visual proxies, UI, picking and persistence. Views never advance agent biology.

`scripts/animal_visual.gd` is a replaceable view with a procedural species silhouette and simulation-time poses. Walking/sprinting legs, grazing head tilt, resting posture, death pose and selected labels freeze when biological time pauses. Forest event views use static cues with no independent timer; changing events while paused changes the chosen intervention but advances no time.

The three behavior layers are deliberately inspectable: needs (hunger/thirst/energy/stamina), prioritized individual decisions shaped by traits and nearby pack activity, and persistent memory of danger, experiences and discovered resources. Remembered danger biases later travel, while resource memories support return journeys. This is lightweight learned avoidance/resource recall, not a neural model. Deer mature at 365 days and wolves at 730 days; both parents require maturity and healthy needs. Biological aging uses 1200 simulation seconds per day. Reproduction is simplified paired spawning with cooldowns; gestation and genetics are not modeled.

Environmental interventions affect resource biomass and animal decisions. Wildlife avoids fire/flood zones, while drought reduces water/food availability. Restoring normal weather allows resource recovery. These are game simulation rules, without fluid dynamics or individual plant models.

Saved `event_elapsed` and `event_intensity` advance only in simulation ticks. Over 180 simulation seconds, wildfire expands from 15 to 30m and flood from 22 to 32m, while event intensity rises from 1x to 2x. Hazard exposure drains needs; exhausted animals in flood water can drown. Wildlife seeks an additional 7m safety buffer. Drought progressively accelerates depletion/thirst; normal weather removes the hazard and allows recovery. Older schema 2 saves missing these fields receive compatible defaults. Forest/map footprints use the same simulation radius.

Save schema is versioned and JSON based. Random state is stored as a string to preserve 64-bit precision. Save on pause and normal window close; load and launch always pause. No wall clock advancement. Autosave uses a temporary file and backup. Invalid saves must leave the current simulation intact.

Save JSON uses full precision; the parser can still round a double by one ULP. Seeded execution is repeatable, while restored floating values are tested within 1e-12, not promised bit-identical replay. Save errors keep the window open on normal close. Saves live under Godot's `user://` directory (normally `%APPDATA%/Godot/app_userdata/North American Ecosystem`); tests redirect APPDATA to ignored `.local/` and restore any prior test saves.

Startup can recover a valid backup when the primary is corrupt. Before replacing a primary, validation determines whether it is safe to become the next backup: valid files rotate to .bak; invalid files are preserved as .corrupt while the previous valid backup remains intact. Manual invalid loads leave the current ecosystem untouched. Follow, focus and restored camera poses all enforce terrain clearance.

Validation: `tools/run_tests.ps1 -Godot <console executable>` runs biological and scene integration tests. Integration covers paused startup, start/step, pause autosave, load paused, state restoration and malformed-save rejection. `-- --capture` runs a graphical viewport capture to ignored test-results/observatory.png; `-- --smoke` starts the full scene, steps and exits. Windows sandbox certificate-store warnings are unrelated to runtime networking (the game uses none).

The runner also includes habitat and acceptance suites and fails on script parse errors. Acceptance injects a real unopenable temporary-save path to verify visible errors, retained disk checkpoints, paused state, prevented destructive reset and event error feedback. Native Windows interaction confirmed Start, Pause/autosave and roster inspection. Follow/map/resource/pruning paths are exercised by scene tests; prolonged subjective playtesting remains separate release qualification.

Expanded QA runs 36,000 ticks representing one simulation hour and checks finite values, bounds, needs, population and save validity every minute. Seed 42 retains both species at one hour, and seeds 7/2026 at 30 minutes. Tests cover maturity, learned avoidance, resource memories, drinking/dehydration, pack coordination, archive pruning and malformed/migrated saves. Scene QA verifies selection/focus/follow, map input, backup recovery, audio generation and 10x fixed-tick scheduling without offline progression. An RTX 5070 graphical benchmark measured about 149 fps over 360 frames at 10x simulation in the default clearing view; this short sample is not a worst-case guarantee.

Runtime assets are replaceable visual proxies. Simulation knows species and position, not mesh structure. Models use original low-poly ellipsoids and simple animated limbs; juveniles scale with age. Future imported models can replace proxies without changing biological state. Original wind/bird ambience is synthesized from filtered noise and sine waves in `forest_audio.gd`; no recordings or sound libraries are bundled. Audio, animal labels and resource markers can be toggled, with preferences saved locally.

The observer map shows animals, resource patches, hazard footprints and camera position. Clicking it moves the camera without advancing the ecosystem. F follows, R focuses, Tab cycles animals. New ecosystem asks before replacing the world and preserves its last state as a recoverable backup. Resource/animal views remove records pruned by load or archive maintenance.

Checkpoints also preserve camera pose, inspected animal, independently followed animal and speed, always loading paused. Optional observer metadata is validated before applying simulation state, and older saves remain compatible. Camera yaw/pitch and follow offset are restored to prevent a first-input snap. Global shortcuts consume their event so focused buttons/rosters cannot swallow or double-trigger Start/Pause.

Graphical QA checked the minimum 1152x720 layout. A 128-record stress scene (36 living plus recent deaths) averaged about 74 fps over 360 frames, and a hazard stress sample about 102 fps, on the RTX 5070 while other game instances were open. These short samples bound the tested scene, not every possible workload; use `-- --benchmark --stress --fresh` to reproduce. Biological coexistence and visual performance are tested separately.

`tools/build_portable.ps1 -Godot <Windows executable>` builds ignored `builds/Windows/Play.cmd` with the local engine and selected project sources. It includes notices from the exact bundled engine plus a SHA256 manifest, without tests, Git data, credentials or local saves. It uses the full engine because export templates are unavailable. This adds no project software license. Engine notice generation follows https://docs.godotengine.org/en/stable/about/complying_with_licenses.html.

Every package is assembled in a fresh staging directory. After a successful manifest is written, the previous Windows bundle is moved into ignored builds/archive and the clean stage becomes builds/Windows. No recursive deletion occurs. A generated unlisted-file fixture verified that stale files remain outside the new distribution; the final directory must contain exactly the manifest's files plus MANIFEST.json.

Research: Godot official documentation on command-line headless execution, saving games and RandomNumberGenerator state informed the testing/persistence design. See https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html and https://docs.godotengine.org/en/stable/classes/class_randomnumbergenerator.html.
